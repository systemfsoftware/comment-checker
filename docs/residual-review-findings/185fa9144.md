Durable record of the seven open issues (#3–#9) after a four-reviewer doc review

## Issue #3 — confirmed-defect

release.yml's tag-reachability gate fetches the default branch with
`--depth=1` and tests ancestry locally, which cannot be trusted for
force-pushed tags.

Evidence: `.github/workflows/release.yml` publishes with
`git fetch origin "$DEFAULT_BRANCH" --depth=1` then
`git merge-base --is-ancestor "$GITHUB_SHA" "origin/$DEFAULT_BRANCH"`.
Session probe (local git, faithful clone): a valid non-tip tag under a
shallow fetch returned "fatal: Not a valid object name" (exit 128) rather
than a trustworthy ancestor answer; the gate rejects or mis-decides
force-pushed and shallow boundary cases. Full-history fetch or an API
containment check is the fix.

## Issue #4 — real-but-corrected

(First-draft verdict `non-issue` — REPUDIATED by the doc review; the
launcher's BinaryNotFound path is live.)

Evidence: `npm/packages/comment-checker/src/index.ts` launcher
`getBinaryPath` resolves `require.resolve(pkg/package.json)` inside
`Effect.try` and raises tagged `BinaryNotFound` with the platform package
name in its message when the platform package is absent. Direct platform
installs can therefore surface BinaryNotFound at runtime.
`scripts/lib/platform-manifest.ts` `buildPlatformManifest` emits
`files: [entry.bin]` — platform packages do ship the binary. The
peerDependencies cross-link suggestion stands (real improvement, severity
overstated).

## Issue #5 — confirmed-defect

A force-moved tag reuses the release lane because the concurrency group
is keyed on the ref, not the commit, and does not cancel.

Evidence: `.github/workflows/release.yml`:
`concurrency: { group: release-${{ github.ref }}, cancel-in-progress: false }`.
Two tag pushes at the same ref serialize in the same lane rather than
guarding a move; the tag can be force-moved between gate and publish.

## Issue #6 — real but corrected

The smoke gate bakes the binary exit contract into YAML; the classifier's
exit-code constant is duplicated, never asserted by the test suite.

Evidence: `.github/workflows/release.yml` smoke step:
`test "$rc" -eq 2 || { echo "flagged payload exit $rc, expected 2" >&2; exit 1; }`.
Severity correction: P3 (already) — real but low; a classifier exit-code
change would break the release at tag time and the YAML asserts the constant
the classifier owns.

## Issue #7 — confirmed-defect (mechanism corrected)

The release cross-check gate reads a sha sidecar file that no workflow step
writes; the digest guard cannot compare anything. (First-draft severity
correction P1->P3 was itself corrected: the guard is inoperative, not merely
partial.)

Evidence: `.github/workflows/release.yml` staging step computes
`SHA="$(sha256_of "$STAGE/${BINARY_NAME}")"` (line 152) and passes it only
via `--binary-sha256 "$SHA"` to `scripts/tools/generate-platform-manifest.ts`
(which writes `package.json` into the staged dir and nothing else). The
upload step lists `${{ runner.temp }}/binary-${{ matrix.suffix }}.sha256`
(line 175) and the cross-check step reads `sidecars/binary-${SUFFIX}.sha256`
(line 277) after `actions/download-artifact` — but no step creates the
`.sha256` file at HEAD (the writer was removed with commit e92d150a). At the
first tag run the artifact upload fails on the missing file or the cross-check
reads an empty sidecar; either way the digest guard never runs its comparison.
Severity: filed P1 retained (mechanism corrected: guard non-functional).

## Issue #8 — confirmed-defect (mechanism corrected)

Verdict mechanism originally drafted as "vacuous pass"; the review and a
session probe show the current gate FAILS LOUDLY instead.

Evidence: `scripts/tools/check-matrix.ts` `checkWorkflow` builds
`workflowPairs` from `content.matchAll(...)` regex over
`RELEASE_WORKFLOW_PATH` (defined in `scripts/lib/shared.ts`), then the
failing loop starts from `tablePairs` (targets.json rows, never empty) and
FAILs every missing row. Probe (this session): taking the 5 targets in a
flow-style `release.yml` yields FAIL for each target and exit 1 — the gate
does not pass vacuously; valid drift variants are falsely rejected. The
regex-extraction approach remains the defect: the fix is a YAML/typed
parse of the matrix rows rather than format-sensitive regexes.

## Issue #9 — confirmed-defect

No actionlint / workflow-YAML / expression-validation gate exists anywhere
in CI; step-syntax or quoting defects in any workflow. Only the tag-run
publish path is the first (and last) gate.

Evidence: `.github/workflows/ci.yml` npm job runs `pnpm lint`, `pnpm build && pnpm typecheck`, `deno task lint`, and `deno task check-matrix` — none of them parses workflow YAML or validates GitHub Actions expressions. `scripts/tools/check-matrix.ts`
`checkWorkflow` regex-scrapes target rows only and validates no other
job/step. "Generic hardening, no project-specific defect" overstated:
the project's only live publish path executes unvalidated workflow edits
at first tag push. Improvement request: actionlint (or YAML-parse +
expression smoke) into the npm CI job for `ci.yml` and `release.yml`.
